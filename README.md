# Thought Library

An interview-practice app with a topic library, question and passage generators, a practice timer, answer recording with feedback, and a history page. Built with React and Vite from the Claude Design handoff below.

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # static site in dist/
```

- **AI features** (question and passage generation, answer feedback, follow-up questions, trend analysis, AI 재구성) call the Claude API (`claude-opus-5-5`) straight from the browser. Paste an Anthropic API key under **AI 설정** in the footer. The key stays in that browser's localStorage. Without a key, every feature falls back to the template and rule-based output the design specified.
- **Data**: `src/data/topics.json` holds the 393 library topics. It is generated by `npm run data`, which replays the prototype's data migrations over `project/*.js`. User edits, notes and answer history are saved in localStorage.
- **Recording**: live transcription uses the Web Speech API, so it works best in Chrome. **✎ 직접 작성** mode works in every browser.

Source layout: `src/App.jsx` holds shared state (library, timer, attempts). Each section is a component in `src/components/`, and the prompts, option sets and constants live in `src/lib/`.

## What you should do — IMPORTANT

**Read the chat transcripts first.** There are 1 chat transcript(s) in `chats/`. The transcripts show the full back-and-forth between the user and the design assistant — they tell you **what the user actually wants** and **where they landed** after iterating. Don't skip them. The final HTML files are the output, but the chat is where the intent lives.

**Read `project/export/Thought Library.html` in full.** The user had this file open when they triggered the handoff, so it's almost certainly the primary design they want built. Read it top to bottom — don't skim. Then **follow its imports**: open every file it pulls in (shared components, CSS, scripts) so you understand how the pieces fit together before you start implementing.

**If anything is ambiguous, ask the user to confirm before you start implementing.** It's much cheaper to clarify scope up front than to build the wrong thing.

## About the design files

The design medium is **HTML/CSS/JS** — these are prototypes, not production code. Your job is to **recreate them pixel-perfectly** in whatever technology makes sense for the target codebase (React, Vue, native, whatever fits). Match the visual output; don't copy the prototype's internal structure unless it happens to fit.

**Don't render these files in a browser or take screenshots unless the user asks you to.** Everything you need — dimensions, colors, layout rules — is spelled out in the source. Read the HTML and CSS directly; a screenshot won't tell you anything they don't.
